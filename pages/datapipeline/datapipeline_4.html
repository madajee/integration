PART-1

There are several benefits to AWS cloud, like on-demand provisioning with pay as you go , economies of scale, go global in minutes, speed and agility, and no capital expenditure on data centers.

There is a shared responsibility model, AWS own responsibility of the cloud and customers own responsibility in the cloud. While architecting solutions and designing services, one can rely on AWS network backbone, physical security and hardware in datacenters and customer is responsible for resources and data in the cloud.

There are several regions that AWS has across the globe and customers can choose a region based on compliance, proximity, feature availability, and price. Developers deploy services and create resources in multiple Availability Zones to create reliabile and fault-tolerant services.

One of the key compute services is AWS EC2, and there are several options available to customers like General Purpose Instances, Compute Optimized, Memory Optimzed, Accelerated compute, Storage Optimized and the workload architecture determines the type of compute instance that you may provision in AWS cloud. Compute layer can be optimized with Auto Scaling and Elastic Load Balancer.

When customer teams have containerized workloads, AWS has ECS and EKS services that can be provisioned with EC2 and AWS Fargate. Lambda is a serverless function-as-a-service offering that provides an option of running the code on different runtimes without provisioning underlying infrastructure resources.

Services like CloudFormation uses templates that can be version-controlled in GIT and automate rapid provisioning and deprovisioning of resources in AWS environments, which helps with rapid prototyping and cost optimization.

Workloads that you deploy on AWS will be composed of several components and services working together to deliver a business value. Some of these services will be public-facing, and others may have to be privately accessible. AWS lets you manage the networking of your environment with resources like Amazon Virtual Private Cloud, Subnet, Security Groups, Network ACLs.
Amazon Virtual Private Cloud (Amazon VPC): An Amazon VPC lets you provision a logically isolated section of the AWS Cloud where you can launch AWS resources in a virtual network that you define.
Subnet: Subnets are used to organize your resources and can be made publicly or privately accessible. A private subnet is commonly used to contain resources like a database storing customer or transactional information. A public subnet is commonly used for resources like a customer-facing website.

There is often a need to store Images, PDF documents, fast read and write to log files, and several groups and teams want to access the files within an enterprise. There are different options available in storage services like Elastic Block Storage for fast read and writes of blocks, Object storage works well for Images and PDF where whole file has to be retrieved or replaced, and Elastic File System for sharing files with standard protocols like NFS/SMB.

There are several operational efforts and cost with on-premise databases like installation, configuration, patching, maintenance tasks, database security, backups, high availability setup, and performance optimization. AWS provides managed database services where most of routine tasks are handled by AWS while customers can design the workloads by fine-tuning storage and retrieval operations on their data. Relational databases can be lifted with AWS RDS or Aurora for MySQL and Postgres, No-SQL workloads can be persisted to DynamoDB, and DataWarehouses can be created in AWS RedShift. Often times, frequently accessed data has to be retrieved and maintained in cache; and the performance of the application can be improved with AWS Elastic Cache, which is a fully managed in-memory caching service.

PART-2

AI training is the process of teaching an AI model to learn patterns from data like text, code, and images, enabling it to perform tasks such as reasoning, problem-solving, and content generation without being explicitly programmed for each one. There are variety of different AWS services for Machine Learning and AI AWS AI/ML stack is composed of three tiers AWS AI Services, AWS ML Services, and highly customizable solutions using frameworks and infrastructure. AI Services are managed offerings that use pre-trained models like Amazon Polly for text-to-speech generation and Amazon Comprehend for text or sentiment analysis. With SageMaker AI, you can build, train, and deploy your own ML models using fully managed infrastructure, tools, and workflows.

AWS Identity and Access Management (IAM) securely manage identities and access to AWS resources and services. Customers are responsible for securing everything they create and manage in the AWS Cloud. This includes the following:

  • Managing the security of data, systems, and applications
  • Deciding what data and workloads to store or run in AWS
  • Determining which AWS services to use
  • Controlling who has access to environments and resources
Users in IAM can be made part of a group and inherit permissions of the group. Permissions are enforced through policies. An IAM policy is a JSON document that describes what API calls a user can or cannot make. Users, groups, and other AWS services can assume roles to perform actions. Roles don’t require static credentials like a username and password and are useful to temporarily grant access to AWS resources, to users, external identities, applications, and even other AWS services.

There are AWS services and tools that will continuously collect, visualize and track the health and performance of the AWS infrastructure, service and applications. Cloudwatch logs centralize the logs from all systems, applications and AWS services that you use. Cloudwatch provides operational visibility by collecting key performance data at user-defined intervals with CloudWatch Metrics, allows you to send alerts with CloudWatch Alarms, and offers a unified view of your resources and applications with CloudWatchDashboards. AWS CloudTrail enable operational and risk auditing, governance and compliance of the AWS account. CloudTrail provides a detailed history of API calls, so you can track changes and identify who made them and when.

There are pricing and billing services like AWS Budgets, Cost Explorer that you can use to manage and optimize AWS costs. While it is simple for a single account, for multiple accounts, the organization setup provides you with a consolidated bill. There are a range of support plans to meet the needs of all AWS customers that range from Basic Support, Developer Support, Business Support, Enterprise On-Ramp Support, Enterprise Support.

There are many tools, services, solutions, and architectures to support migration to AWS Cloud. The three phases of the migration process are Assess, Mobilize, Migrate and Mordernize. In the Assess phase, one can use Pre-Migration Assessment tools like Migration Evaluator, in the Mobilize phase one can use Migration Tools like AWS Application Discovery Service, AWS Migration Hub, and in the migrate and modernize phase one can use AWS Application Migration Service and AWS Data Migration Service. There are data transfer tools like AWS Data Sync, AWS Transfer Family, AWS SNOW family to move the data from on-premise to AWS cloud.

The AWS Well-Architected Framework is based on six pillars — operational excellence, security, reliability, performance efficiency, cost optimization, and sustainability. The are design principles and best practices in each pillar that provide consistency to the workload architecture, and the framework tool can be used to evaluate the overall design and improve on it.
